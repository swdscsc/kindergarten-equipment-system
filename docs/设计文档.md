# 园务设备管理系统 — 设计文档

> 版本：v1.0（2026-10-31） · 本项目为个人技术演示作品，数据为虚构示例。

## 1. 需求背景与目标

幼儿园集团（三所园区）的设备管理长期依赖手工 Excel：台账分散、报修口头传达、月度统计靠人工汇总。本项目目标是构建一个**真实可运行**的设备管理信息系统，覆盖：

1. 设备资产登记与查询（台账）
2. 报修登记与维修全过程留痕（维修记录）
3. 管理层视角的实时统计与可视化（看板）
4. 与既有办公流程兼容的 Excel 报表输出（导出）

同时以该系统为数据源，产出 Word 月度报告、PPT 培训课件与数据录入规范，形成"系统 + 制度 + 培训"的完整行政信息管理方案。

## 2. 总体架构

```
┌─────────────────────────────────────────────┐
│                浏览器（中文界面）              │
│   Jinja2 渲染页面  +  Chart.js 客户端图表      │
└──────────────┬──────────────────┬───────────┘
               │ HTML/POST        │ GET /api/stats (JSON)
┌──────────────▼──────────────────▼───────────┐
│              Flask 应用 (app/)               │
│  routes.py   表单校验 · 状态机 · 路由         │
│  db.py       SQLite 访问 · 建表 · 种子数据    │
│  excel_export.py  openpyxl 报表引擎           │
└──────────────┬──────────────────────────────┘
               │ sqlite3（单文件库）
        instance/kindergarten.db
```

**技术选型与理由**

| 选型 | 理由 |
|------|------|
| Flask | 轻量、代码即文档，适合演示系统结构与教学场景部署 |
| SQLite | 零配置单文件数据库，演示环境免安装服务；`sqlite3.Row` 以字典方式取值 |
| Chart.js（本地化 vendored） | 无外网依赖，图表原生可交互；配色与办公交付物统一 |
| openpyxl | 生成带公式、数据验证、条件格式的原生 xlsx，而非静态值堆砌 |
| pytest + Flask test client | 无需浏览器即可覆盖路由、校验、状态机与导出内容 |

## 3. 数据模型

```sql
devices (
  id, code UNIQUE, name, category, park,
  purchase_date TEXT 'yyyy-mm-dd',
  value REAL, status TEXT, keeper TEXT
)
repairs (
  id, order_no UNIQUE, device_id → devices.id,
  fault_type, report_date, finish_date NULL,
  status TEXT, cost REAL
)
```

**枚举词表**（与《Excel 数据录入规范》一致，代码中为唯一定义点 `db.py`）：
- 园区：阳光园 / 彩虹园 / 星辰园
- 设备状态：在用 / 维修中 / 闲置 / 待报废
- 维修状态：待派单 / 维修中 / 已完成
- 故障类型：机械损坏、制冷异常、电路故障、软件故障、耗材老化、触控失灵、管路漏水、光学部件、进纸卡纸、噪音异常

**报修单号规则**：`WX-YYMM-XX`，XX 为当月顺序号（查询前缀 + 取最大值 +1），由 `next_order_no()` 生成，避免人工编号跳号重号。

## 4. 核心业务规则（状态机）

```
登记报修 ──▶ 单据「待派单」 ──▶ 「维修中」 ──▶ 「已完成」(必填完成日期+费用)
   │                                                  │
   ▼ 设备状态联动                                       ▼ 设备状态联动
「在用」→「维修中」                          「维修中」→「在用」
```

- 报修时设备状态为「在用」→ 自动改为「维修中」
- 维修单标记已完成且设备当前为「维修中」→ 自动恢复「在用」
- 若设备在维修期间被人工改为其他状态，系统不覆盖人工设置（以先判断 `dstatus == '维修中'` 为条件）
- 含未完结维修单的设备**禁止删除**（数据完整性保护），引导走「待报废」处置流程

**服务端校验清单**（`routes.py::_device_form_errors` 等）：
必填项、日期格式（`datetime.strptime` 严格校验）、金额为非负数字、编号唯一（新增与编辑分别处理）、枚举合法性、未知设备编号拒绝、已完成必须提供完成日期。

## 5. 页面与接口设计

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/` | 管理看板：6 项 KPI + 3 张图表 |
| GET | `/api/stats` | 看板图表数据（JSON：园区分布、故障分布、月度趋势） |
| GET | `/devices` | 台账列表（园区/状态/关键字筛选） |
| GET/POST | `/devices/new`、`/devices/<id>/edit` | 新增 / 编辑设备 |
| POST | `/devices/<id>/delete` | 删除（有维修单时拒绝） |
| GET | `/repairs` | 维修记录列表（状态/园区筛选，内联更新表单） |
| GET/POST | `/repairs/new` | 登记报修（自动编号、状态联动） |
| POST | `/repairs/<id>/update` | 状态流转（已完成校验完成日期与费用） |
| POST | `/repairs/<id>/delete` | 删除维修记录 |
| GET | `/export.xlsx` | 实时导出四表工作簿 |

**视觉设计**：深青主色 `#15857A` + 橙色点缀 `#FF6A3B`（与 Excel 看板、PPT 配色同源），白底卡片、圆角 12px、状态彩色胶囊标签，微软雅黑字体，适配 ≥1280px 桌面并兼容窄屏（媒体查询降级网格）。

## 6. Excel 报表引擎设计

`excel_export.py` 从数据库实时重建交付版工作簿：

1. 设备台账 / 维修记录：数据 + 下拉数据验证（DataValidation）+ 条件格式（维修中红、待报废琥珀）
2. 月度统计：写入**活公式**（COUNTIF / COUNTIFS / SUMIFS / IFERROR），打开文件即重算，保持"报表可审计"
3. 管理看板：KPI 单元格引用公式区
4. 数字格式：货币 `¥#,##0.00`、日期 `yyyy-mm-dd`、百分比 `0.0%`

## 7. 测试设计

分层测试（见 [测试报告](测试报告.md)）：页面可达性、筛选查询、CRUD 正反用例、状态机联动、单号规则、导出内容（openpyxl 回读断言）。20 个用例全部通过。

## 8. 已知边界与后续计划

- 单机演示定位：无登录与权限体系（生产化路线：Flask-Login + 角色权限，对应《录入规范》中的岗位分工）
- 统计月份区间当前为演示固定 2026-06~10（生产化：按参数动态生成）
- 报修单暂无附件上传（IAB 演示环境限制；生产化方案已预留）
