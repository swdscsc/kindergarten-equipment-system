# 面试问题及回答准备

> 结合本项目《园务设备管理系统》，按"高频问题 + 参考回答要点"整理。回答时结合截图与代码走查，避免空谈。

## 一、项目介绍类

**Q1：请用一分钟介绍这个项目。**
> 这是一个我独立完成的幼儿园集团设备管理系统，解决三个园区的设备台账、报修维修、月度统计问题。技术上用 Flask + SQLite 做后端，Chart.js 做看板图表，openpyxl 做报表引擎——导出的 Excel 里写的是活的 COUNTIFS/SUMIFS 公式，管理员打开还能继续用。系统有 20 个 pytest 用例覆盖，我用浏览器完整演示过报修流程：登记 SB-010 报修后，系统自动生成单号 WX-2610-05，设备状态自动变成维修中，看板 KPI 实时从 4 变 5。系统数据还延伸产出 Word 月报、PPT 培训和录入规范文档，形成完整方案。

**Q2：为什么选 Flask + SQLite，而不是 Django 或 MySQL？**
> 这是单机演示系统，核心诉求是"结构清晰、讲解成本低、开箱即跑"。Flask 应用工厂 + 蓝图足够表达 MVC 分层；SQLite 零配置、单文件，演示和测试都用临时目录隔离。如果用户量上来，数据访问都封装在 db.py，把 sqlite3 换成 SQLAlchemy + PostgreSQL 影响面可控。

## 二、技术设计类

**Q3：设备状态和维修单状态怎么保证一致？**
> 我把联动做成了显式状态机：登记报修时，设备如果是"在用"就自动置为"维修中"；维修单标记"已完成"时，只有设备当前是"维修中"才恢复"在用"——加这个条件是因为管理员可能在这期间手工把设备改成"闲置"或"待报废"，系统不能覆盖人工操作。另外有未完结维修单的设备禁止删除，防止孤儿维修单。

**Q4：Excel 导出是怎么做的？和普通导出有什么区别？**
> 用 openpyxl 从数据库实时生成。区别在于我导出的是"活报表"：月度统计区写的是 COUNTIFS、SUMIFS 公式而不是算好的数值，日期区间用 `">="&DATE(2026,6,1)` 拼接，除法全部套 IFERROR；台账的状态列加了下拉数据验证和条件格式。这样行政人员拿到文件后可以继续录入、筛选、重算。导出的文件我用 LibreOffice 无头模式做过公式重算质检，204 个公式零错误。

**Q5：表单校验在哪里做？为什么不放前端？**
> 服务端统一校验：必填、日期用 strptime 严格校验（2026/01/01 这种斜杠格式直接拒绝）、金额非负数字、编号唯一、枚举词表合法性。前端只做 required 提示。原因是这些规则和《数据录入规范》制度是同一套口径，放服务端只有唯一定义点（routes.py），改一处全端生效，也方便测试直接覆盖。

**Q6：报修单号 WX-2610-05 是怎么生成的？**
> 前缀 WX-YYMM- 加当月两位顺序号。生成时查询同前缀的最大序号加一。SQLite 单写入者场景下这个"查最大再插入"是安全的；如果并发要求高，我会改成独立序列表加事务，或者数据库自增列拼接。

**Q7：看板图表数据从哪来？**
> 前端 fetch /api/stats 拿 JSON，Chart.js 渲染。聚合 SQL 放在后端（COUNT/GROUP BY），前端不做业务计算。Chart.js 我做了本地化（vendored），演示环境不依赖外网。

## 三、测试与质量类

**Q8：这个项目怎么测试的？发现了什么问题？**
> pytest + Flask test client，20 个用例分四组：看板与统计 API 聚合、台账 CRUD 与筛选、维修状态机正反用例、Excel 导出后用 openpyxl 回读断言。每个用例用临时目录独立建库，互不污染。最有价值的是首轮测试就抓出 4 个真实缺陷：LIKE 子句里多打个 `]` 导致 500、INSERT 占位符和列错位、sqlite3.Row 列表被当字典索引、openpyxl 的 StyleProxy 不可哈希赋值。修完 20 个全绿，缺陷记录在测试报告里。

**Q9：如果让你加一个功能，比如报修审批流，你怎么做？**
> 先在《录入规范》层面明确流程（谁审批、什么条件触发），再加 repairs 表的 approve 字段与"待审批"状态，状态机扩一档；审批动作记录操作人和时间；测试补审批通过/驳回两条路径；最后看板增加"待审批数"KPI。制度和代码同步改，这是我这个项目一贯的做法。

## 四、办公与管理能力类

**Q10：这个系统和 Excel 台账比，优势在哪？**
> 三点：一是录入约束前置，状态下拉、编号唯一在系统里是硬校验，Excel 里靠自觉；二是统计实时，看板不用等人月度汇总；三是留痕，谁报修、什么时候修完、花多少钱都有单号可查。但我没有把 Excel 推翻——导出报表保持了原来的公式习惯，制度上写了两者如何衔接，这更符合行政场景的渐进式替换。

**Q11：如果幼儿园老师不会用系统怎么办？**
> 我配套做了 12 页的《信息设备使用与维护培训》课件和《Excel 数据录入规范》。培训设计是"先讲怎么用、再讲坏了怎么办、最后讲数据怎么录"，报修流程压缩成五步图，只要求老师记住设备编号加故障现象，其余由信息管理员完成——把学习成本压到最低。

## 五、诚信与边界类

**Q12：这是真实项目吗？**
> 明确说：这是我的个人技术演示项目，数据是我构造的虚构示例（32 台设备、20 条维修记录），没有在任何真实幼儿园部署使用。我做的所有测试结果、截图都是本项目真实运行产生的，可以现场复现。

**Q13：如果要上生产，你还要补什么？**
> 用户登录与角色权限（对应规范里的教师/信息员/主管三级）、操作审计日志、数据备份策略（规范里写了每周备份，系统层再加自动任务）、HTTPS 与部署（gunicorn + nginx）、以及把演示写死的统计月份参数化。
